### Agent Implementation

| Part | Implementation |
|---|---|
| **Percepts** | Question text, chat history, retrieved passages and diagrams, tool results |
| **Actions** | `search_documents`, `read_section`, `read_page`, `find_code`, `respond_to_user`, `insufficient_evidence`, `ask_clarifying_question` |
| **Decisions** | Rewrite a follow-up; search again or reply; answer, ask for clarification, or decline |
| **State** | `QueryState` for each turn; the last 5 question-and-answer turns; documents cited in the last 2 answers (max 30) |
| **Environment interaction** | Hybrid search of the manual database; LLM and embedding services over HTTP |
| **Terminal behavior** | Ends with an answer, a clarifying question, an insufficient-evidence reply, no relevant documents, or an error; searching stops after 3 rounds or 300 s |

## 2. Architecture and Interaction

```text
OFFLINE INGESTION
  PDF manuals -> load -> parse (text, tables, diagrams) -> layout and sections
              -> chunk -> embed -> Chroma

ONLINE QUERY (one turn)
  User (CLI or web app)  <---------------------------------------------+
        | question + chat history                                      |
        v                                                              |
  user_query -> rewrite_query -> embed_query                           |
        |                                                              |
        v                                                              |
  vector_store_search  <--- Chroma + BM25 + part numbers / codes       |
        |                                                              |
        v                                                              |
  add_history_documents --- no documents ---> "No relevant documents" -+
        |                                                              |
        v                                                              |
  generate_response (LLM)  <------>  search_more                       |
        |                            (max 3 rounds / 300 s)            |
        | answer | clarifying question | insufficient evidence         |
        v                                                              |
  process_tool_call (check citations, attach diagrams) ----------------+
```

## 5. Measure Definitions

| Measure | Type | Definition | Direction |
|---|---|---|---|
| Case pass rate | Quality | Cases where every check on every turn passes. Checks cover reply kind, rewrite contents, retrieved and cited file and page, required and forbidden facts, clarify options, diagrams and search limits, with expected values taken from the manuals | Higher is better |
| Check pass rate | Quality | Individual checks passed out of all checks | Higher is better |
| Failed checks by stage | Quality | Failed checks grouped by rewrite, retrieval, decision (reply kind) and answer | Lower is better |
| Rewrite pass rate | Quality | Cases with a scripted history, judged only on the rewritten search query | Higher is better |
| Extra searches per turn | Efficiency | Agent tool calls after the first retrieval | Lower is cheaper, but 0 on a turn that needed more context is a failure |
| Model calls per turn | Cost | Agent turns plus rewrite calls plus extra searches (retries not counted) | Lower is better |
| Elapsed time per turn | Efficiency | Wall-clock time of a full suite run divided by graded turns | Lower is better |
| Pipeline errors | Reliability | Turns that ended in an error | Lower is better |
