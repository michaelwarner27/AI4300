- Diagram context

- Hybrid search

## 1. Implemented Refinement

**Baseline:** the U0-HW-11 vertical slice (commit `8c5486a1`, `tests/results/query_results_HW11.txt`): 12 single-turn questions on 7 manuals.
- Graded with today's checks, it passed 9 of 12: Q04 put its citation in the answer text instead of the sources list, Q06 returned no diagram, and Q08 missed the Dometic filter interval.
- It made one search and one LLM call per question.
- It had no conversation history, so it cannot run the multi-turn cases.

**Pre-change reference for the new cases:** commit `e7bf3c45`, report `query_results_005.txt`. This is the earliest version that can run all 61 original cases: the U0-HW-11 agent plus conversation history, section-aware ingestion and hybrid search, on the 49-manual corpus.
- It passed 46 of 61 cases (failed checks: answer 15, decision 6, rewrite 4).
- It searched again on only 5 of 73 turns.
- Its failures motivated the four changes made for this checkpoint.

| Change (commit) | Evidence | Expected effect |
|---|---|---|
| **Section-aware ingestion, diagram context, conversation history, hybrid search** (`64aa5854`, `4ce5e5e6`): chunks carry their heading path, diagrams carry their section and caption, earlier turns and their cited documents carry over, and dense search is blended with BM25 and exact part-number matching | U0-HW-11: Q06 returned no diagram; Q08 missed the Dometic interval; no keyword or part-number search; one search per question; no follow-up questions possible | Diagrams and the right section returned; part numbers found; multi-turn conversations possible |
| **Exact-code lookup** (`ac49b559`): short codes such as `E1` trigger a whole-word search inside the retrieved manuals; matches are listed first; a `find_code` tool does the same on request | `E1` now appears in 48 chunks (it was in 2 with 7 manuals), so it lost its exact-match boost. For "E1 on the CCC2", every one of the top 10 hits contained `E1`, but the expected CCC2 diagnostic-sheet passage was not among them | Short codes resolve to the manual that was asked about |
| **Follow-up rewriting** (`b7597f00`): rules for clarification replies, corrections and topic switches; long earlier answers keep their start and end; the model is told when older turns are no longer shown | RW13 rewrote "the last command" as command 19 of 20; M04 presented the oldest visible turn as the first question; C01 rewrote "5 button" as "CCC 2" | Correct search queries for follow-ups |
| **Named models and clarifying questions** (`01e962b6`): question words that match a manual's filename ("5 button", "non-ducted") add that manual's passages; the agent sees which manuals are in context; a which-model checklist; no second clarifying question in a row | C01 never retrieved the 5-button manual and gave 4-button steps under a 5-button citation; C03 and C04 answered for one model without asking | Answers come from the named model's manual; clarifying questions when manuals disagree |
| **Answer checks** (`98ebc061`): "not covered" answers become insufficient-evidence replies; citations to pages that were never retrieved are corrected or dropped; named manuals contribute their best passage from each of their 5 closest sections | S06 and S09 said "not covered" as a normal answer; C12 cited a page that does not exist; the Blizzard roof-limit passage ranked about 8th inside its manual but 4th to 5th by section | Correct reply types, trustworthy citations, and the right section reaches the agent without an extra search |

Supporting changes:
- Subfolder ingestion (`b234b6b0`), needed for the nested corpus.
- The graded multi-turn harness (`3014e89c`) and its cases (`1b196452`).

## 2. Measure Definitions

| Measure | Definition | Direction |
|---|---|---|
| Case pass rate | Cases where every check on every turn passes. Checks are reply kind, rewrite contents, retrieved and cited file and page, required and forbidden facts, clarify options, diagrams and search limits, with expected values taken from the manuals | Higher is better |
| Check pass rate | Individual checks passed out of all checks | Higher is better |
| Failed checks by stage | Failed checks grouped by rewrite, retrieval, decision (reply kind) and answer | Lower is better |
| Rewrite pass rate | `--rewrite-only` cases: 17 cases with a scripted history, judged only on the rewritten search query | Higher is better |
| Extra searches per turn | Agent tool calls after the first retrieval | Lower is cheaper, but 0 on a turn that needed more context is a failure |
| Model calls per turn | Agent turns plus rewrite calls plus extra searches (retries not counted) | Lower is better |
| Elapsed time per turn | Wall-clock time of a full suite run divided by graded turns | Lower is better |
| Pipeline errors | Turns that ended in an error | Lower is better |

## 4. Representative Examples

All excerpts are from report `query_results_016.txt`.

### Successful

**C01.** A generic question, then a model named in words. The pre-change version gave 4-button steps under a 5-button citation.

> **User:** How do I reset my thermostat?
> **HaRVey (clarify):** Which thermostat model are you using? The reset procedure differs depending on whether you have a CCC 2 or a CT thermostat. Options: Dometic CCC 2 thermostat; Dometic CT thermostat
> **User:** The 5 button Comfort Control Center.
> **HaRVey:**
> 1. Turn the ON/OFF switch to the "OFF" position.
> 2. Simultaneously depress and hold the MODE and ZONE push-buttons while turning the ON/OFF switch to "ON".
> 3. Release the MODE and ZONE push-buttons once "FF" appears in the LCD display.
>
> Each step cites: 5 Button Comfort Control Trouble Shooting Bulletin, p.8, 16. SYSTEM RESET

**R11.** A short code that about 47 chunks share.

> **User:** What does error code E5 mean on the CCC2 thermostat?
> **HaRVey:** On the CCC2 thermostat, error code E5 indicates that the **Freeze Sensor is Open or Out of Range** ... Air conditioner and dehumidification operation will be locked out ...
>
> Sources: CCC2-Operating-Instructions.pdf (page 10, LCD Error Code); two Dometic service-manual pages

**C03 turn 1.** Graded a failure, because the test expects a clarifying question, but the answer is correct and labelled by model.

> **User:** How thick can my roof be for a Blizzard air conditioner install?
> **HaRVey:**
> - Ducted Model: minimum of 2 inches and maximum of 5 inches.
> - Non-Ducted Model: minimum of 1-3/4 inches and maximum of 3-3/4 inches.
>
> Sources: both Blizzard installation manuals, page 4, SPECIFICATIONS > B. Roof Requirements

### Unsuccessful or limited

**R10.** The newer revision says black pin #2; the agent cited only the older revision and did not mention the conflict.

> **HaRVey:** ... measure between pin #4 (yellow) and pin #4 (black).
>
> Source: 205579_NAUTILUS (IW60) ODWH_STM, RB, 04-10-2019.pdf (page 18)

**S08.** It correctly warned against a VOM and a screwdriver, but also listed a method that contradicts the RVIA capacitor sheet:

> **Using a voltmeter:** You may discharge capacitors with a standard voltmeter if you use a scale over 500 volts and touch the leads to each side of the capacitor.

### Assessment

- These examples show why I added the clarifying question option for the agent.
- Especially as the database gets larger finding the specific make and model is crucial for getting accurate information.
- This is also why adding the hybrid search was a top priority for me in this project.

## 5. Limitations

- **Single runs** at temperature 0.7. During development, C07, C10, M06 and Q08 changed outcome between runs of nearly the same code (reports 013, 014 and 016), so a difference of one or two cases is within run-to-run variation.
- **U0-HW-11 comparison:**
  - Only Q01-Q12 can be compared directly, and the U0-HW-11 run used 7 manuals instead of 49.
  - Its answers were graded afterwards from the saved results file, so retrieval details are not available.
  - Q04 fails only because its citation sat in the answer text instead of the sources list.
- **Changed expectations:** nine test expectations were corrected after reading the pre-change replies (report 005). Five were loosened because they rejected acceptable replies (Q02, RW08, S03, C01, and R01's cited page), three were tightened because they passed wrong ones (C08, C10, S08), and one was reworded (M03). The headline comparison uses only unchanged cases.
- **Grader limits:**
  - Facts are checked with regular expressions, so wording can slip past a pattern; S08 passed twice before its pattern was widened.
  - A reply better than expected can fail (C03).
- **Scope:**
  - One LLM and one embedding model.
  - 49 of about 500 available manuals, chosen to stress the agent.
  - No real user questions.
- **Known gaps:**
  - No OCR, so image-only pages are unreadable.
  - No handling of conflicting revisions or sources (R10, S08).
  - Clarify options are limited to retrieved manuals (C13).
  - The agent rarely searches again on its own.
  - Named-manual matching depends on descriptive filenames.
- **Cost:** elapsed time includes the shared LLM server's load at the time of each run; context size not measured.

### Limitation Assessment

- Adding OCR is one of the first gaps that I want to plug. The llm can only provide answers as good as the data it has.
- I have also yet to test it on more complex questions that may arise in the real world.
- It could be fun to deploy this version and get some feedback from actual RV technicians.
